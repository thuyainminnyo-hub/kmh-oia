## 1. Research findings

The Library of Congress BagIt Conformance Suite defines RFC-version-specific fixture groups:
- valid bags expected to exit successfully;
- invalid bags expected to exit non-zero;
- optional warning bags that remain valid but should emit warning output;
- Linux-only and Windows-only invalid fixtures.

The upstream harness runs a validator CLI using conventional exit codes and captures stdout/stderr. The suite README warns that Git `core.autocrlf` conversion can change fixture bytes and cause validation failures.

References:
- https://github.com/LibraryOfCongress/bagit-conformance-suite
- https://www.rfc-editor.org/rfc/rfc8493.html

The official bagit-python README documents `python -m bagit --validate` as a supported CLI invocation, and states that SHA-256 and SHA-512 are generated by default. RFC 8493 requires BagIt 1.0 tools to support both algorithms and recommends SHA-512 by default. BagIt hashes provide corruption/fixity checking but are not authentication against active attacks.

References:
- https://github.com/LibraryOfCongress/bagit-python
- https://www.rfc-editor.org/rfc/rfc8493.html

## 2. Implementation

Added `scripts/run_bagit_conformance.py`:
- discovers v1.0 fixture groups;
- skips OS-specific fixtures not applicable to the current runner;
- runs the pinned bagit-python validator for each fixture;
- checks valid/invalid exit-code expectations;
- requires warning fixtures to remain valid and surface stderr warning output;
- records each fixture's category, expected result, exit code, stdout, stderr and pass/fail;
- emits a machine-readable JSON report with suite commit, validator version, Python version, platform and run timestamp.

Updated `.github/workflows/preservation-gate-a.yml`:
- checks out LOC BagIt Conformance Suite at pinned commit `9ab48705c06664f9f419ca740c728c9f89a61e7c`;
- disables Git line-ending conversion before the suite checkout;
- runs the Gate A unit tests and LOC fixture runner;
- uploads the JSON conformance report as a GitHub Actions artifact even when later steps fail;
- triggers when the conformance runner changes on pull requests and branch pushes.
